# 安全审核报告

**最近更新**: 2026-08-12  
**仓库**: https://github.com/defeatd/firemail-perfect  
**审核版本**: v1.2.1（已关闭全部 API 限速；凭证脱敏、死代码清理等）

## 执行摘要

对 FireMail 邮箱管理系统进行了安全与代码质量评估，并在后续迭代中修复多项问题。适合 **Tailscale / 内网私有部署**；公网多租户场景仍需加强凭证保护。

### 当前发现统计（代码态）

| 严重程度 | 数量 | 说明 |
|---------|------|------|
| 🔴 严重 (Critical) | 0 | 需立即修复 |
| 🟠 高危 (High) | 0 | 需优先修复 |
| 🟡 中危 (Medium) | 2 | 邮箱凭证明文落库；JWT 存 localStorage |
| 🔵 低危 (Low) | 若干 | 上传无大小限制、CSP 缺失等 |

### 已修复 / 已加固

1. **JWT 密钥一致**：Flask 与 WebSocket 共享 `jwt_config.py`
2. **列表 API 脱敏**：`password` / `refresh_token` 脱敏，`access_token` 置空
3. **凭证按需下发**：`GET /api/emails/<id>/password` 与 `/credentials`，带审计日志
4. **附件下载**：`Content-Disposition` 安全编码（RFC 5987）
5. **管理员权限**：check / update / realtime 属主策略对齐
6. **API 限速**：已全部关闭（含登录/注册/导入/Device Code/凭证），私有部署优先易用性
7. **死代码清理**：移除未使用的 `backend/apis`、`backend/websocket`、`backend/db`、`EmailList.vue` 及备份文件
8. **邮件排序**：按绝对接收时间由新到旧（兼容历史时区字符串）

### 仍需关注

| 事项 | 建议 |
|------|------|
| 邮箱 password / refresh_token 明文存 SQLite | 应用层加密敏感列；保护 `data/` 与备份 |
| JWT 在 localStorage | 优先 HttpOnly Cookie；收紧 CSP 与邮件 HTML 净化 |
| 生产 `JWT_SECRET_KEY` | 必须自定义（compose 已强制） |
| 注册开放时首用户=管理员 | 公网部署应关闭注册或强管控 |
| 无限速 | 公网暴露时建议在反向代理层做 IP 限流 |
