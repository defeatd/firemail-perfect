# FireMail 邮箱管理系统 - 安全审核报告

**审核日期**: 2025-12-25
**审核版本**: v1.0.0
**审核人**: Claude Code Security Auditor
**严重程度评级**: 🔴 高风险

---

## 执行摘要

本次审核对 FireMail 邮箱管理系统进行了全面的安全与代码质量评估。**发现了多个严重安全漏洞**，需要立即修复后才能投入生产环境使用。

### 关键发现统计

| 严重程度 | 数量 | 说明 |
|---------|------|------|
| 🔴 严重 (Critical) | 4 | 需立即修复，可能导致数据泄露 |
| 🟠 高危 (High) | 6 | 需优先修复，存在明显安全风险 |
| 🟡 中危 (Medium) | 8 | 建议修复，影响安全性或可维护性 |
| 🔵 低危 (Low) | 5 | 可选修复，属于最佳实践建议 |

### 最严重问题（必须立即修复）

1. **明文密码存储** - 数据库同时存储明文密码和哈希密码
2. **硬编码 JWT 密钥** - 默认密钥公开在代码中
3. **CORS 配置为通配符** - 允许任意域访问 API
4. **OAuth Token 明文存储** - access_token 和 refresh_token 未加密

## 第一部分：严重安全漏洞 (Critical)

### 1.1 🔴 明文密码存储

**位置**: `backend/database/db.py:84-85, 347, 367`

**问题描述**:
数据库表 `users` 同时存储 `password`（明文）和 `password_hash`（哈希），违反 OWASP 密码存储最佳实践。

```python
# db.py:347 - create_user 函数
(username, password, password_hash, salt, 1 if is_admin else 0)
#          ^^^^^^^^ 明文密码被存储！

# db.py:367 - update_user_password 函数
(new_password, password_hash, salt, user_id)
# ^^^^^^^^^^^^ 明文密码被存储！
```

**风险等级**: 🔴 严重
**OWASP 映射**: A02:2021 – Cryptographic Failures

**攻击场景**:
- 数据库泄露后，攻击者直接获取所有用户明文密码
- 可用于撞库攻击其他网站
- 违反 GDPR 等数据保护法规

**修复建议**:
```python
# 1. 移除数据库中的 password 列
# 2. 修改 create_user 函数，只存储哈希
self.conn.execute(
    "INSERT INTO users (username, password_hash, salt, is_admin) VALUES (?, ?, ?, ?)",
    (username, password_hash, salt, 1 if is_admin else 0)
)
```

---

### 1.2 🔴 硬编码 JWT 密钥

**位置**: `backend/app.py:49`

**问题描述**:
JWT 签名密钥使用硬编码默认值，任何人都可以伪造有效 token。

```python
JWT_SECRET = os.environ.get('JWT_SECRET_KEY', 'huohuo_email_secret_key')
#                                              ^^^^^^^^^^^^^^^^^^^^^^^^ 公开的默认密钥！
```

**风险等级**: 🔴 严重
**OWASP 映射**: A02:2021 – Cryptographic Failures

**攻击场景**:
- 攻击者使用默认密钥伪造管理员 token
- 完全绑过身份验证
- 获取任意用户的邮箱数据

**修复建议**:
```python
import secrets

JWT_SECRET = os.environ.get('JWT_SECRET_KEY')
if not JWT_SECRET:
    # 生产环境必须设置环境变量
    if os.environ.get('FLASK_ENV') == 'production':
        raise RuntimeError("JWT_SECRET_KEY must be set in production!")
    # 开发环境自动生成（每次重启都会变化）
    JWT_SECRET = secrets.token_hex(32)
    logger.warning("Using auto-generated JWT secret for development")
```

---

### 1.3 🔴 CORS 配置过于宽松

**位置**: `backend/app.py:34, 42-45`

**问题描述**:
CORS 配置允许任意域访问 API，存在跨站请求伪造风险。

```python
CORS(app, supports_credentials=True, resources={r"/api/*": {"origins": "*"}})
#                                                           ^^^^^^^^^^^^^ 危险！

response.headers.add('Access-Control-Allow-Origin', '*')
#                                                   ^^^ 与 credentials 冲突
```

**风险等级**: 🔴 严重
**OWASP 映射**: A01:2021 – Broken Access Control

**修复建议**:
```python
# 从环境变量读取允许的域
ALLOWED_ORIGINS = os.environ.get('ALLOWED_ORIGINS', 'http://localhost:3000').split(',')

CORS(app,
     supports_credentials=True,
     resources={r"/api/*": {"origins": ALLOWED_ORIGINS}})
```

---

### 1.4 🔴 OAuth Token 明文存储

**位置**: `backend/database/db.py:105-106`

**问题描述**:
OAuth 的 access_token 和 refresh_token 以明文存储在数据库中。

```sql
-- emails 表结构
refresh_token TEXT,   -- 明文存储
access_token TEXT,    -- 明文存储
```

**风险等级**: 🔴 严重
**OWASP 映射**: A02:2021 – Cryptographic Failures

**修复建议**:
- 使用对称加密（如 AES-256-GCM）加密 token 后存储
- 加密密钥通过环境变量配置
- 建议使用 `cryptography` 库

## 第二部分：高危安全问题 (High)

### 2.1 🟠 Cookie Secure 标志禁用

**位置**: `backend/app.py:178`

```python
response.set_cookie(
    'token',
    token,
    httponly=True,
    max_age=7*24*60*60,
    secure=False,  # ❌ 生产环境应为 True
    samesite='Lax'
)
```

**修复建议**: 根据环境变量动态设置

---

### 2.2 🟠 密码策略过弱

**位置**: `backend/app.py:222-224`

```python
if len(password) < 6:  # ❌ OWASP 建议最少 8 个字符
```

**OWASP 建议**:
- 最小长度 8 个字符
- 检查常见弱密码列表
- 不限制字符类型
- 使用密码强度计

---

### 2.3 🟠 Token 存储在 localStorage

**位置**: `frontend/src/services/api.js:64`

```javascript
localStorage.removeItem('token');  // ❌ 容易被 XSS 攻击窃取
```

**修复建议**: 使用 httpOnly Cookie 或 sessionStorage

---

### 2.4 🟠 环境变量泄露到控制台

**位置**: `backend/app.py:52-56`

```python
for key, value in os.environ.items():
    if key in ['JWT_SECRET_KEY', ...]:  # ❌ 打印敏感信息
        print(f"{key}: {value}")
```

**修复建议**: 生产环境禁用此代码

---

### 2.5 🟠 SQLite 线程安全问题

**位置**: `backend/database/db.py:73`

```python
self.conn = sqlite3.connect(db_path, check_same_thread=False)
# ❌ 多线程环境下可能导致数据竞争
```

**修复建议**: 使用连接池或每线程独立连接

---

### 2.6 🟠 缺少速率限制

**问题**: 登录、注册等敏感 API 没有速率限制，容易被暴力破解。

**修复建议**: 使用 Flask-Limiter

```python
from flask_limiter import Limiter
limiter = Limiter(app, key_func=get_remote_address)

@app.route('/api/auth/login', methods=['POST'])
@limiter.limit("5 per minute")
def login():
    ...
```

## 第三部分：中危问题 (Medium)

### 3.1 🟡 密码哈希算法不符合 OWASP ASVS

**位置**: `backend/database/db.py:276-283`

当前使用 PBKDF2-SHA256，迭代次数 100000。虽然可接受，但 OWASP 推荐：
- 首选 Argon2id
- 或 bcrypt（工作因子 10+）
- PBKDF2-SHA256 需要 600,000+ 次迭代

---

### 3.2 🟡 缺少 CSRF 保护

WebSocket 和部分 API 缺少 CSRF token 验证。

---

### 3.3 🟡 生产环境调试日志过多

大量 `console.log` 和 `logger.info` 输出敏感信息。

---

### 3.4 🟡 附件存储为 BLOB 无限制

**位置**: `backend/database/db.py:140`

```python
content BLOB,  # ❌ 无大小限制，可能导致数据库膨胀
```

---

### 3.5 🟡 JWT 过期时间过长

**位置**: `backend/app.py:151`

```python
'exp': datetime.datetime.utcnow() + datetime.timedelta(days=7)
# ❌ 7 天过长，建议 1 小时 + refresh token 机制
```

---

### 3.6 🟡 邮箱密码明文存储

**位置**: `backend/database/db.py:99`

```python
password TEXT NOT NULL,  -- 邮箱密码明文存储
```

---

### 3.7 🟡 前端同时使用 Pinia 和 Vuex

**位置**: `frontend/package.json:24, 28`


### 3.8 🟡 缺少输入验证和清理

## 结论

FireMail 项目在功能实现上较为完整，但存在**多个严重安全漏洞**，**不建议在修复前投入生产环境**。

最紧迫的问题是**明文密码存储**和**硬编码 JWT 密钥**，这两个问题可能导致用户数据完全泄露。

建议按照本报告的优先级路线图进行修复，并在修复后进行渗透测试验证。
